# ICEHOME 桌面端（Electron）

> 配套：[项目计划书](./项目计划书.md) · [任务目标](./任务目标.md) · [部署与存储](./部署与存储.md)

## 1. 目标

桌面端不是第二套业务系统，而是给现有面板加一层可安装的壳：

- 双击即可用，不要求用户先安装 Node、再手动 `npm start`。
- 内置「本地模式」与「远程模式」，同一个启动器里切换。
- 本地模式在应用内启动完整服务，保留账户、设备、平面图、二维码与巡检能力。
- 远程模式连接 NAS、小主机或已运行的 8787 服务，复用同一套 Web UI。
- Windows / macOS / Linux，x64 与 arm64 都可打包；本地服务为纯 JS，无需按 CPU 架构重编。
- 多端：本地模式可监听局域网，手机/平板用浏览器访问同一份数据；远程模式可保存多个服务器。

## 2. 架构

```text
Electron 主进程 main.cjs
├─ 启动器 BrowserWindow（preload 暴露受限 IPC）
│  ├─ 本地模式：端口 / 监听范围 / 数据目录 / 启动状态
│  └─ 远程模式：根地址 / 健康检查 / 常用服务器 / 自签名证书
├─ 本地服务 runtime.js（与 CLI 共用）
│  ├─ persistence（JSON / PostgreSQL / MySQL）
│  ├─ cache（内存 / Redis）
│  ├─ Express app（/api /v1 + dist 静态资源）
│  └─ 调度器、seed、二维码、巡检
└─ 面板 BrowserWindow（不注入 preload）
   ├─ 本地模式：http://127.0.0.1:<实际端口>
   └─ 远程模式：<远程根地址>
```

关键约束：

- 本地服务直接跑在 Electron 主进程里，不额外 spawn 系统 Node，因此安装包不依赖用户环境。
- `server/src/runtime.js` 是 CLI 与桌面端共用的唯一启动入口；`server/src/index.js` 只负责读环境变量、打日志、处理退出信号。
- 远程面板窗口没有 preload、`nodeIntegration=false`、`sandbox=true`；远程页面拿不到桌面 IPC。
- 启动器窗口才有 `preload.cjs`，只暴露状态查询、连接、选择目录、测试地址、复制文本等白名单方法。

## 3. 双模式

### 3.1 本地模式

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 端口 | `8788` | 被占用时自动向后尝试最多 10 个端口 |
| 监听 | `0.0.0.0` | 可在启动器改为「仅本机 127.0.0.1」 |
| 数据目录 | `<userData>/data` | 启动器可改为项目现有 `data` 目录 |
| 账号 | seed `admin / icehome` | 与 Web 面板完全一致 |
| 局域网 | `http://<网卡 IPv4>:<端口>` | 启动后启动器与托盘可复制地址 |

本地模式自动处理：

- 数据目录首次启动写 seed；后续复用。
- 同一数据目录加 `.icehome.lock`，CLI 与桌面端不会同时写 `db.json`。
- 端口被占用自动顺延，并在状态里显示实际端口。
- 关闭应用时先 `store.flush()`，再关闭缓存/存储/HTTP。

> 如果把桌面端指向项目现有 `data`，请先停掉 8787 的 CLI 服务。锁会拒绝第二个写入者，但不要删除锁文件来绕过。

### 3.2 远程模式

- 输入服务器根地址，例如 `http://192.168.1.10:8787`；只允许 `http/https`，不允许路径、查询、账号口令。
- 先请求 `<origin>/api/health`，显示延迟、服务名与版本；失败不打开面板。
- 连接成功后自动保存到「常用服务器」，去重、最多 8 个。
- HTTPS 自签名证书需要显式勾选「允许当前远程主机的自签名证书」；只对这个 hostname 放行，不全局关闭校验。
- 远程模式不启动本地服务；切换时关闭本地 runtime，释放端口与数据锁。
- 远程面板的登录、成员权限、二维码、巡检全部由远程服务端决定。

## 4. 多 CPU、跨平台、多端

### 4.1 CPU 架构

`package.json > build` 使用 electron-builder：

| 平台 | 目标 | 架构 |
| --- | --- | --- |
| Windows | NSIS | x64 / arm64 |
| macOS | DMG | x64 / arm64 |
| Linux | AppImage | x64 / arm64 |

`pg`、`mysql2`、`redis` 都是纯 JS 依赖；Express、React 也不含原生扩展，所以同一份 `server/` 可以在 Electron 自带的 Node 上运行，不需要 `node-gyp` 或按架构重编。

### 4.2 CI 矩阵

`.github/workflows/desktop.yml` 在 tag `v*` 或手动触发时运行：

- `windows-latest`：`--win --x64`、`--win --arm64`
- `macos-13`：`--mac --x64`
- `macos-14`：`--mac --arm64`
- `ubuntu-latest`：`--linux --x64`、`--linux --arm64`

每个矩阵先 `npm ci`、`npm test`、`npm run build`，再 `electron-builder ... --publish never`，最后上传安装包。macOS 未配置签名/公证，产物用于内部分发；公开发布需补 Apple Developer ID 与公证。

### 4.3 多端

- 同一局域网：本地模式监听 `0.0.0.0`，手机浏览器访问启动器/托盘里复制的 `http://<IPv4>:<port>`。
- 多个服务端：远程模式保存多个常用地址，一键切换 NAS / 小主机 / 本机。
- 同一服务多端：账户与设备授权由服务端统一管理，桌面端与浏览器看到同一份状态。

## 6. 开发与打包

```bash
npm install
npm run desktop:dev       # 构建 dist 后启动 Electron
npm run desktop:dist:dir  # 未压缩目录，便于本地验收
npm run desktop:dist      # 当前平台安装包
npm run test:desktop      # 本地/远程双模式 E2E
```

本机 Windows 的未压缩产物在 `release/win-unpacked/`，安装包在 `release/ICEHOME-<version>-win-<arch>.exe`。`release/` 已加入 `.gitignore`。

本机已验证：

- `npm run desktop:dist:dir` 生成 `release/win-unpacked/`。
- 直接启动 `release/win-unpacked/ICEHOME.exe`，本地模式启动 8788 并打开面板，`data/db.json` 落盘。
- `npx electron-builder --win nsis --x64 --publish never` 生成 `release/ICEHOME-1.0.0-win-x64.exe`（未签名）。
- `npx electron-builder --win nsis --arm64 --config.directories.output=release-arm64 --publish never` 生成 `release-arm64/ICEHOME-1.0.0-win-arm64.exe`；arm64 包未在 x64 主机上运行，只验证了打包链路。
- live `8787` 已重启到带锁 runtime：数据锁记录 PID，10 台设备、10 个平面标记、2 个启用任务均保留；再启动第二个 runtime 会返回“数据目录已被进程 18348 使用”。

macOS/Linux 与 arm64 运行由 CI 矩阵构建；本机 Windows x64 验证了 x64 未压缩目录、x64 安装包与打包后启动。首次在无符号链接权限的 Windows 账户上打包时，`winCodeSign` 解压会因 macOS dylib 符号链接失败；本机通过预置已修复的 `winCodeSign` 缓存绕过后成功。CI 的 Linux/macOS runner 不受此限制。

启动器支持的环境变量（主要用于测试与隔离）：

| 变量 | 作用 |
| --- | --- |
| `ICEHOME_DESKTOP_USER_DATA` | 覆盖 Electron `userData`（设置、日志、窗口位置） |
| `ICEHOME_DESKTOP_DATA_DIR` | 覆盖本地模式默认数据目录 |

## 7. 安全设计

- 启动器：`contextIsolation=true`、`sandbox=true`、`nodeIntegration=false`，只通过 preload 白名单调用 IPC。
- 面板窗口：不加载 preload；本地与远程使用不同 `persist:` 分区，登录令牌按 origin 隔离。
- 导航：面板窗口只允许留在当前 origin，新窗口/外链交给系统浏览器。
- 远程证书：默认走 Chromium 校验；只有显式勾选自签名且 hostname 完全匹配时才放行。
- 远程地址：拒绝 `file:`、`javascript:`、带账号口令、带路径/查询的地址。
- IPC：连接参数在主进程重新校验，不信任渲染进程传入的端口/路径。
- 本地服务：数据目录锁、端口顺延、写前 flush；局域网模式会在启动器提示“手机需用账户登录”。
- 托盘菜单只做打开/复制/重启/退出，不提供任意命令执行。

## 9. 已知限制

- 未接入自动更新；升级需重新安装。
- Windows 安装包未签名，SmartScreen 可能提示；macOS 产物未签名/公证，Gatekeeper 可能提示。
- 未做单实例多窗口；重复启动会聚焦已有窗口。
- 关闭窗口在 Windows/Linux 会随托盘继续驻留；需从托盘菜单退出。
- 远程模式依赖 `/api/health`，非 ICEHOME 服务即使能打开网页也会被拒绝。
- 本地模式把服务跑在主进程里，极端情况下服务端 CPU 密集逻辑会影响窗口响应；当前业务量下可接受。
- 摄像头扫码仍依赖 Chromium 的 `BarcodeDetector`，与浏览器端限制一致。

## 10. 故障排查

| 现象 | 检查 |
| --- | --- |
| 本地模式端口被占用 | 启动器会显示实际端口；也可手动换端口 |
| “数据目录已被进程使用” | 先停掉占用该目录的 CLI/桌面端，或换数据目录 |
| 远程模式连接被拒绝 | 确认服务已启动、地址是根地址、防火墙放行端口 |
| 自签名 HTTPS 失败 | 勾选“允许当前远程主机的自签名证书” |
| 页面空白 | 菜单「视图 → 开发者工具」查看加载错误；确认 `dist/` 已构建 |
| 打包后找不到 runtime | 确认 `electron-builder` 的 `files` 包含 `server/`、`dist/`；当前 `asar=false` |
