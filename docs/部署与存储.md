# ICEHOME 部署与存储

本文覆盖四项扩展能力：数据库存储、Redis 缓存、页面缓存、前后端分离部署，以及配套的代理网关示例。

## 1. 架构

```
                    ┌──────────────────────────────┐
浏览器 / API 客户端 →│  nginx 或 examples/gateway    │
                    │  静态 dist + 反向代理          │
                    └───────────────┬──────────────┘
                                    │ /api、/v1
                    ┌───────────────▼──────────────┐
                    │  Express API                  │
                    │  ├─ 认证（Bearer Token）       │
                    │  ├─ 页面缓存中间件（可选）      │
                    │  ├─ 领域引擎 / 调度器           │
                    │  └─ persistence 适配器          │
                    └───────┬───────────────┬──────┘
                            │               │
                 ┌──────────▼───┐   ┌───────▼────────┐
                 │ JSON 文件     │   │ PostgreSQL /   │
                 │ data/db.json │   │ MySQL          │
                 └──────────────┘   └────────────────┘
                            │
                    ┌───────▼────────┐
                    │ Redis（缓存）   │  可选，连接失败自动降级内存
                    └────────────────┘
```

- 存储层是「整份状态文档」模型：业务代码仍然读写 `store.data`，持久化适配器负责把文档写入 JSON / SQL。表结构固定为 `icehome_state(id, doc, updated_at)`，文档 id 为 `default`。
- 缓存层只缓存 GET 响应，写请求成功后自动失效；默认关闭，避免刚写入就读到旧数据。
- 前后端分离由 `SERVE_STATIC` 与 `CORS_ORIGINS` 两个开关控制，前端构建时用 `VITE_API_BASE` 指向 API 域名。
- 桌面端复用 `server/src/runtime.js`：本地模式在主进程内启动同一套 Express 服务，远程模式只作为浏览器壳连接现有服务。打包产物见 `release/`，多架构矩阵见 `.github/workflows/desktop.yml`，细节见 [桌面端](./桌面端.md)。

### 1.1 桌面端与数据目录

- 桌面端默认数据目录是 Electron `userData/data`，与 CLI 的 `data/` 分开；启动器可手动指向项目 `data`，适合从 CLI 迁移。
- 同一数据目录启动时写 `.icehome.lock`（记录 PID）。CLI 或桌面端已占用时，第二个进程会拒绝启动，避免两个进程同时覆盖 `db.json`。
- 桌面端默认监听 `0.0.0.0:8788`，端口被占用会顺延；手机访问用启动器/托盘复制的 `http://<网卡 IPv4>:<端口>`。
- 远程模式保存根地址，连接前请求 `/api/health`；家用 HTTPS 自签名证书需在启动器显式勾选，且只对当前 hostname 放行。

## 2. 数据库存储

### 2.1 选择驱动

| `STORAGE_DRIVER` | 连接串 | 说明 |
| --- | --- | --- |
| `json`（默认） | 不需要 | 写入 `data/db.json`，原子替换 |
| `postgres` | `postgres://user:pass@host:5432/db` | 自动建表，`jsonb` 存储文档 |
| `mysql` | `mysql://user:pass@host:3306/db` | 自动建表，`longtext` 存储 JSON |

不写 `STORAGE_DRIVER` 时按 `STORAGE_URL`（兼容 `DATABASE_URL`）协议推断；Redis 协议会被拒绝，因为它只能做缓存。

### 2.2 PostgreSQL

```powershell
$env:STORAGE_DRIVER = 'postgres'
$env:STORAGE_URL = 'postgres://icehome:password@127.0.0.1:5432/icehome'
npm start
```

服务启动时会执行：

```sql
CREATE TABLE IF NOT EXISTS icehome_state (
  id text PRIMARY KEY,
  doc jsonb NOT NULL,
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

首次启动且表为空时，会写入一份种子数据；之后每次保存使用 `INSERT ... ON CONFLICT (id) DO UPDATE`。

### 2.3 MySQL

```powershell
$env:STORAGE_DRIVER = 'mysql'
$env:STORAGE_URL = 'mysql://icehome:password@127.0.0.1:3306/icehome'
npm start
```

```sql
CREATE TABLE IF NOT EXISTS icehome_state (
  id varchar(64) PRIMARY KEY,
  doc longtext NOT NULL,
  updated_at timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

写入使用 `INSERT ... ON DUPLICATE KEY UPDATE doc = VALUES(doc)`。

### 2.4 依赖与降级

`pg`、`mysql2`、`redis` 已声明为 `optionalDependencies`，已随本仓库安装。若在裁剪后的环境里缺少驱动，启动时会给出明确提示：

```
[ICEHOME] 启动失败：PostgreSQL 驱动未安装：请执行 npm i pg，或改用 STORAGE_DRIVER=json
```

### 2.5 数据迁移

完整配置备份在面板「二维码巡检 → 配置二维码 → 下载配置文件」生成，返回 `settings / categories / devices+adapter / tasks / plugins / plans`，不含账户、令牌与事件；配置二维码本身只编码 10 分钟有效的只读下载短链。该 JSON 适合审计与换机参考，当前不在面板内提供一键恢复。

`GET /api/export` 仍只导出设备清单 bundle（名称/模板/能力/状态/分类名），`POST /api/import` 接收的是 `icehome://import?payload=…` 或该 bundle 的 base64url，合并分类、跳过重复插件并重建设备 ID，不是整份文档覆盖导入。

```powershell
# 设备清单二维码内容（bundle 的 payload）
curl.exe -H "Authorization: Bearer <token>" http://127.0.0.1:8787/api/export -o bundle.json
```

旧版 `db.json` 没有 `users` / `plans` / `settings.wifi` / `inspections` 时，服务启动会自动迁移：补一个 `admin` 账户（`admin / icehome`）、一个演示成员 `family`、一张「一层平面」并把现有设备按分类放进房间；同时补默认 Wi-Fi 配置与空巡检数组。迁移只补缺失结构，不覆盖已有账户、平面、巡检或设备。

升级后若旧管理员口令不是初始值，可在「账户与权限」页编辑 `admin` 重设口令；已有 `sk-ice-…` 独立令牌不受影响，仍按原 scope 工作。

## 3. Redis 与页面缓存

### 3.1 连接 Redis

```powershell
$env:REDIS_URL = 'redis://127.0.0.1:6379'
$env:CACHE_PREFIX = 'icehome:'
npm start
```

- 连接成功：`[cache] Redis（前缀 icehome:）`，缓存写入 Redis。
- 连接失败：自动降级为进程内存，启动日志与「设置 → 存储与缓存」会显示降级原因，服务不中断。

### 3.2 页面缓存规则

| 规则 | 行为 |
| --- | --- |
| 生效范围 | 仅 `GET`，且路径属于 `state / devices / categories / tasks / plugins / events / ai/manual` |
| 缓存键 | `<token.id>:<原始 URL>`，不同令牌互不命中 |
| TTL | 设置页可调，1 - 120 秒 |
| 失效 | 任意非 GET 请求且状态码 < 400 时清空全部页面缓存 |
| 旁路 | 请求头 `Cache-Control: no-cache` 跳过缓存，响应 `x-cache: BYPASS` |
| 开关 | 默认关闭；设置页开启后立即生效 |

响应头 `x-cache` 取值 `HIT / MISS / BYPASS`，便于排查。

### 3.3 相关接口

```http
GET  /api/cache/stats       # 缓存后端、命中/未命中、条目数、TTL
POST /api/cache/purge       # 清空缓存，需要 admin
POST /api/system/storage/test  # 测试当前存储连接，需要 admin
GET  /api/system            # 含 storage 与 cache 的运行时快照
```

`GET /api/state` 的 `infra` 字段也会返回存储驱动、连接状态与缓存统计，供前端展示。

### 3.4 为什么默认关闭

现有集成测试与使用习惯都假设「写入后立刻读到新值」。缓存开启后，最多会有一个 TTL 窗口的延迟（写请求会主动清空，正常不会出现陈旧数据）。默认关闭可以让升级过程零行为变化，再由使用者在设置页按需开启。

## 4. 前后端分离

### 4.1 单进程（默认）

```powershell
npm run build
npm start
```

后端同时托管 `dist`，`http://127.0.0.1:8787` 直接可用。

### 4.2 分离部署

```powershell
# 终端 A：只提供 API
npm run start:api            # 等价于 SERVE_STATIC=false npm start

# 终端 B：静态资源 + 代理
npm run start:gateway        # examples/gateway，默认 8790
# 或使用 nginx：deploy/nginx/icehome.conf
```

前端构建时如果 API 在不同域名：

```powershell
$env:VITE_API_BASE = 'https://api.example.com'
npm run build
```

### 4.3 跨域

API 进程设置允许来源（逗号分隔）：

```powershell
$env:SERVE_STATIC = 'false'
$env:CORS_ORIGINS = 'http://127.0.0.1:5173,https://panel.example.com'
npm start
```

CORS 中间件会回显匹配的 `Origin`，允许 `authorization / content-type / x-ice-token / cache-control` 请求头，并对 `OPTIONS` 直接返回 204。

### 4.4 开发模式

```powershell
npm run dev:server
npm run dev:web
```

Vite 会把 `/api`、`/v1` 代理到 `ICE_API_TARGET`（默认 `http://127.0.0.1:8787`），前端代码中 `VITE_API_BASE` 留空即可。

## 5. 代理案例

仓库提供两套等价实现：

| 方案 | 文件 | 适用 |
| --- | --- | --- |
| Node 零依赖网关 | `examples/gateway/server.mjs` | 单机、内网、演示；自带 Redis/内存页面缓存与 `/__gateway/stats` |
| nginx | `deploy/nginx/icehome.conf` | 生产；TLS、HTTP/2、静态资源长缓存、SSE 不缓冲 |

Node 网关要点：

- 静态托管 `dist`，未知路径回退 `index.html`。
- `/api`、`/v1` 反代到 `GATEWAY_UPSTREAM`，`/v1` 使用流式转发，SSE 不被缓冲。
- `GATEWAY_CACHE_TTL` 控制网关层只读缓存（默认 5 秒，0 关闭）；配置 `REDIS_URL` 时落 Redis，否则用内存。
- 缓存键包含令牌指纹，避免越权命中；写请求成功后清空 `gw:*`。
- `GET /__gateway/stats` 返回命中率、失效次数、上游错误等指标。

详见 `examples/gateway/README.md`。

| 变量 | 默认 | 作用 |

| `CACHE_PREFIX` | `icehome:` | 缓存键前缀 |
| `SERVE_STATIC` | `true` | `false` 时只提供 API |
| `CORS_ORIGINS` | 空 | 允许跨域来源，逗号分隔 |
| `ICE_TICK_MS` | `15000` | 调度器心跳 |
| `VITE_API_BASE` | 空 | 前端构建时的 API 根地址 |

| `GATEWAY_CACHE_TTL` | `5` | 网关页面缓存秒数 |

## 7. 验证与排查

本机实际验证范围：

- JSON 存储读写、驱动解析、SQL 连接失败提示与密码脱敏：已实测。
- Redis（本机 6379）：连接成功、缓存 `MISS → HIT`、`/api/cache/purge` 清空均实测通过。
- Redis 不可达（指向关闭端口）：自动降级内存并在 `/api/system` 返回 `fallbackReason`，实测通过。
- PostgreSQL / MySQL：本机未运行数据库实例，因此**未做真实建表与读写联调**；驱动加载、连接串校验、连接失败提示与密码脱敏已覆盖。接入真实实例时按第 2 节配置即可。

```powershell
npm test                 # 单元 + 集成
npm run test:e2e         # Playwright（内部会先构建）
npm run build
```

常见问题：

| 现象 | 排查 |
| --- | --- |
| 启动报「驱动未安装」 | 执行 `npm i pg` / `npm i mysql2`，或改回 JSON |
| 启动报连接失败 | 检查连接串、数据库是否允许远程、防火墙 |
| 界面显示「Redis 不可用」 | Redis 未启动或密码错误；服务已降级内存，可正常使用 |
| 缓存一直是 MISS | 设置页未开启、TTL 为 0、请求方法非 GET，或请求头带了 `Cache-Control: no-cache` |
| 读到旧数据 | 检查是否有写操作走了非标准路径；可用 `POST /api/cache/purge` 手动清空 |
| 跨域失败 | `CORS_ORIGINS` 是否包含完整来源（含协议与端口） |
| 前后端分离后接口 404 | 网关是否把 `/api`、`/v1` 反代到 API，而不是落到静态回退 |

## 8. 安全提示

- 数据库连接串含密码，日志与界面使用 `redactUrl` 脱敏；不要把 `.env` 提交到仓库。
- Redis 建议只在内网监听，必要时启用 ACL；缓存内容包含设备快照，等同业务数据。
- 跨域来源请写精确域名，避免使用 `*` 搭配凭证。
- `x-ice-token` 仅用于兼容旧客户端，优先使用 `Authorization: Bearer`。
- 初始管理员口令 `icehome` 只用于首次进入，部署到局域网后应立即在「账户与权限」修改；成员口令同样由管理员设置。
- 登录令牌与独立令牌都等同于家庭控制权，按最小授权原则只给成员必要的设备；停用账户会立即让会话失效。
- 登录失败节流是单进程内存计数，多实例/反代部署时应在网关层再加限流。
- `settings.wifi` 含 Wi-Fi 口令：管理员 `/api/state` 可见，成员快照只给 SSID/加密方式/是否有口令；Wi-Fi 二维码与配置导出仅 admin。配置二维码是 10 分钟有效的免 Bearer 下载短链，拿到链接即可读取配置，展示与截图应按敏感信息处理。
- 反代部署时配置二维码的下载地址取 `X-Forwarded-Proto` / `X-Forwarded-Host`；未设置时会回退到本机网卡 IPv4 + 当前端口，确保手机在同一 Wi-Fi 可访问。
- 网段扫描仅 admin，且只接受 `10.x / 172.16-31.x / 192.168.x / 127.x` 的 `/24-/32`；单次最多 8 个端口、254 台主机，探测超时 350ms、并发 32。HTTP/TLS/RTSP/MQTT 端口会做协议握手，避免裸 TCP 被网络中间层误判为全部开放；未知端口回退 TCP。不会尝试登录设备。不要把面板暴露到公网后开放 admin 账户。
